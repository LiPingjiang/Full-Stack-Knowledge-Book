# 第十三章 · 案例研究：国际化外卖数据开发——多时区、多语言、多币种下的数仓建设

> 以某国际化外卖平台为案例，分析一个"流量/营销域数仓 + 数据中台基建 + 数据治理 + AI 知识库"的复合型数据研发岗位：为什么国际化外卖的数仓建设比国内外卖多了三个维度（时区、语言、币种），为什么它既要求维度建模硬功夫又要求 RAG 知识库能力，以及哪些能力属于通用数仓工程，哪些能力是国际化场景特有的。

## 本章定位

这一章和第十二童略有不同：它直接对应一份真实 JD 的逐条拆解。这份 JD 来自一家出行平台旗下国际化外卖业务线，岗位要求的核心关键词是"流量或营销方向数仓建设 + 三层建模体系 + 大数据全栈 + 数据治理 + AI 知识库 + 英语能力"。

这个岗位的独特价值在于：它把传统数仓建设和 AI 基建放在了同一个 JD 里。这意味着候选人不仅要会 ODS/DWD/DWS/ADS 分层建模和 Spark/Flink/Hive 调优，还要懂向量数据库选型、Embedding 流水线、RAG 检索增强——这是 2025-2026 年数据工程岗位的新趋势：数据团队不再只服务 BI 看板，还要支撑 AI 语义检索和智能问答。

从国际化外卖的业务特点可以直接反推出几个关键信号：
- 多国多时区运营意味着传统的"北京时间 0 点调度一次"模式完全失效，数仓需要做多时区班车改造；
- 多语言场景下维度表、搜索词分析、埋点数据都要处理多语言问题；
- 多币种要求指标跨 region 汇总时必须做汇率折算；
- 营销归因在国际化场景下面临更复杂的触点链路（不同国家的 APP 版本、支付方式、营销玩法可能完全不同）。
