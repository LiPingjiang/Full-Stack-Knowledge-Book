# 15.3 通用知识补缺与章节回链：把第六、七章的知识串成体系

> 先给全局：这个 JD 压中了全书第六、七章的主脊。回链不是「把链接贴一遍」，而是回答三个问题：哪些既有知识可以直接迁移、哪些要按生物医药场景改造、哪些是全书没覆盖的真缺口（留给 [15.4](./04-领域知识：生物医药研发数据实体标准与Ontology.md)）。

## 一、可直接迁移：你的数据工程存量资产

对一个做过数据研发/数据平台的候选人，下面这些能力是这个岗位的「老本」，面试时应主动把它们翻译成 JD 语言：

| 既有能力（章节） | JD 中的对应表述 | 迁移要点 |
|---|---|---|
| 数据仓库分层与维度建模（[6.7](../part6-bigdata/07-数据仓库设计.md)） | 「数据湖/数据管道」「AI-ready 高质量数据体系」 | raw/standardized/curated/derived 四层就是数仓分层的领域版；「核心实体表」= 维度建模里的核心维度，只是实体从「用户/商品」换成「靶点/分子/研究」 |
| 数据质量（[6.14](../part6-bigdata/14-数据质量.md)） | 「数据质量指标」「Agent 质检」 | 六维度质量框架直接可用；新增两个生物医药维度：**证据等级**（这条结论来自几级证据）和**来源许可**（这个数据能不能商用） |
| 元数据与血缘（[6.19](../part6-bigdata/19-元数据管理与智能数据治理.md)） | 「Data Catalog、血缘追踪、Tagging」 | 方法论整体迁移；AI 辅助元数据生成（LLM 打标签、自动发现实体）在这个 JD 里被明确点名，是「用 AI 做数据」的主战场 |
| 多租户与权限（[6.17](../part6-bigdata/17-多租户与权限体系.md)） | 「数据分级分类、访问控制、审计追溯」 | Ranger 式的行列级权限 + ABAC 是 ToB 私有化的硬需求；生物医药新增「同意（consent）」和「用途限制」作为权限维度，不只是密级 |
| 数据接入与集成（[6.16](../part6-bigdata/16-数据接入与数据集成.md)） | 「整合外部专业数据库」「私有数据接入」 | CDC/批量/API 三种接入模式对应 ELN/LIMS 导出、公共数据库版本化快照、客户系统 API；公共库的「版本化快照」是本场景特有的接入形态（每次全量快照，保留更新审计） |
| 任务调度（[6.13](../part6-bigdata/13-任务调度.md)） | 「数据管道」 | 初创用轻量方案（一个 Airflow/DolphinScheduler 实例足够），但**任务可重跑、幂等、可回放**的设计纪律不能省——因为评测要求「相同输入和版本下复现结果」 |

## 二、需要按场景改造的：AI 应用栈

第七章的知识在这个岗位全部用得上，但每一项都要做「生物医药改造」：

**RAG（[7.1](../part7-ai-engineering/01-RAG实战.md)、[7.11](../part7-ai-engineering/11-检索平台工程.md)）：** 分块策略、混合检索、Reranker 的工程框架不变，改造点有三。其一，**分块必须尊重文档结构**——专利的权利要求、文献的摘要/方法/结果、SOP 的条款，切穿结构边界会摧毁可解释性。其二，**Embedding 对专有名词失效**，基因名、靶点别名、化合物的 SMILES 码在通用向量空间里语义模糊，必须靠 BM25 + 术语归一（查询改写成标准 ID 集合）兜底。其三，**检索结果要带元数据**（质量状态、证据等级、许可、权限），元数据过滤在检索层而不是生成层执行。

**GraphRAG（[7.10](../part7-ai-engineering/10-GraphRAG与知识图谱.md)）：** 实体关系抽取、社区发现、Local/Global Search 的方法论不变，但生物医药的图谱有**先天优势**：实体类型是封闭集合（靶点、疾病、药物、通路……），不像通用 GraphRAG 要从开放文本里猜实体。这意味着抽取 pipeline 的 schema 可以预先定义、用 SHACL 约束校验，准确率天花板远高于通用场景——这是垂直领域的结构性红利，面试值得主动讲。

**Agent（[7.6](../part7-ai-engineering/06-Agent基础.md)）：** Function Calling / MCP / 多 Agent 的机制不变，改造点是**权限分级成为第一公民**（见 [15.2](./02-生物医药数据与AI基础设施架构全景.md) 的分级表）。通用 Agent 面试讲「怎么让任务成功率更高」，这个岗位的 Agent 面试讲「怎么让它失败时无害」——沙箱、幂等键、双人复核、调用回放，这些词要像讲限流熔断一样熟练。

**AI 安全（[7.9](../part7-ai-engineering/09-AI安全与可信.md)）：** Prompt 注入防御、PII 脱敏、多租户隔离直接迁移。生物医药新增两类敏感对象：**患者数据**（临床/PV 场景的合规红线）和**客户 IP**（ToB 场景的商业红线）。JD 里「防高敏信息被 Agent 不当使用」的技术答案是检索层权限过滤 + 工具层参数校验 + 审计层调用回放，**提示词里写『禁止泄露』只是仪式**——这句话要能在面试里说出口。

**微调与蒸馏（[7.5](../part7-ai-engineering/05-微调入门.md)）：** JD 职责 3 里「专家 CoT 思维链沉淀、偏好库建设、蒸馏」是后训练数据工程的活。要点是这些数据来自客户现场和内部科学家，**采集本身需要数据契约**（谁批准的、什么用途、能不能进训练集），否则交付过程中顺手把客户数据变成训练语料是合同事故。

**大模型数据工程（[6.8](../part6-bigdata/08-大模型数据工程.md)）：** 去重、质量过滤、配比的方法论迁移到「文献 + 分子 + 蛋白 + 序列」多模态语料。业界已公开验证的技术路线（把文献、分子、蛋白、测序、图谱压缩进统一多模态框架）意味着数据负责人要回答：**多模态怎么配比、专业语料的污染检查怎么做、版本怎么冻结**——这题在面试「懂模型如何消费专业数据」时会出。

## 三、真正的缺口：第六、七章没覆盖的

按重要度排序，这些是准备这个岗位必须新建的知识，全部在 [15.4](./04-领域知识：生物医药研发数据实体标准与Ontology.md) 展开：

1. **生物医药领域数据本身**：药物研发流程决定数据形态；靶点/疾病/通路/分子/专利/临床/BD 交易这些实体的字段、权威源、脏数据模式。这是最大缺口，占准备时间的 60%。
2. **领域标准体系**：CDISC（临床提交）、FHIR（医疗交换）、OMOP（观察性研究）、SEND（临床前）的分工，以及「复用标准优先、领域模型自建」的判断。JD 里没有点这些名，但「建立领域 Ontology/语义体系/知识表示标准」这条职责的业界答案是这套体系。
3. **GxP 与监管边界**：GxP/ALCOA+/Part 11 是什么、为什么生成式 AI 在临床/PV/CMC 只能当受控草稿、FDA/EMA 的 AI 监管动向。不需要背法条，需要的是「知道哪些动作在哪些域永远不能自动化」的边界感。
4. **公共数据库生态与许可**：ChEMBL、UniProt、ClinicalTrials、专利库等的字段结构、更新频率、学术/商用许可差异。这直接决定成本模型，「深度使用过」的考察就落在这里。
5. **中文术语映射层**：中文监管/专利/诊疗文本到标准概念的映射，机器翻译不得直接写入受控术语主表。这是中国市场的特有工程问题，也是本土团队的差异化机会。

## 四、学习路径建议（两周突击版）

面向「通用数据工程背景 + 零生物医药背景」的候选人，时间盒两周：

第一周建立骨架：先用半天读 [15.4](./04-领域知识：生物医药研发数据实体标准与Ontology.md) 的「药物研发流程与数据形态」，建立全局地图；然后动手——下载 ChEMBL 的一个靶点（如 EGFR）的全部关联化合物记录，亲手数一数字段、看看别名有多少种写法，比读十篇综述都有用；再花两天在 UniProt / ClinicalTrials.gov 上重复这个练习，重点是观察「同一个实体在不同库里长什么样」。

第二周串体系：把 [15.2](./02-生物医药数据与AI基础设施架构全景.md) 的蓝图对着业界七案例读一遍，画出自己的裁剪版；然后做那道试金石题——用任意技术栈搭「靶点—疾病—文献证据」的最小可查原型（哪怕只有 100 个靶点、500 篇摘要），亲手体验实体对齐的脏活。最后一天留给 GxP 边界和中文映射层的概念扫盲。

对已有生物医药背景的候选人，路径反过来：把两周投在上面第二、三节的回链上——数据治理、RAG/Agent 工程化、评测体系，用 [15.2](./02-生物医药数据与AI基础设施架构全景.md) + [15.5](./05-面试准备.md) 的方案题自测。
