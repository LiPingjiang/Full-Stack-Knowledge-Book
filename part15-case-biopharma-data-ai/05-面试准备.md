# 15.5 面试准备：初创 90 天计划、实战题、反问与尽调清单

> 先给全局：负责人级面试考的不是知识点复述，而是三个判断——**你会怎么规划（战略层）、你会怎么取舍（架构层）、你能不能自己干（执行层）**。本章按这三个层次组织：先给自我定位叙事，再给初创版 90 天计划，然后是实战题集，最后是反问与尽调——对天使轮公司，候选人尽调公司和公司考察候选人同样重要。

## 一、自我定位叙事：三分钟开场白

负责人面试的开场白要同时回答「你是谁、你懂什么、你怎么干」。建议骨架：

> 我的数据工程底座是【数仓/数据平台 N 年 + 具体系统】，这块对应 JD 的治理与基础设施；我深度做过【知识图谱/RAG/评测的具体项目】，并且有一手经验证明数据组织方式决定 AI 效果——【一个具体案例：实体没对齐时检索错误率 X%，对齐后降到 Y%】；生物医药领域我系统补过【实体模型/标准体系/动手做过 ChEMBL 数据】，清楚知道自己哪块强、哪块要和领域专家配对干活。对创业公司，我的预期是前三个月我自己写最难的 pipeline，团队是随着交付长出来的。

三个要点：**有一手案例**（数据质量 → 模型效果的因果链，这是整份 JD 最看重的判断力）；**坦诚领域边界**（声称全懂生物医药反而减分，「我知道怎么和科学家配对」是加分的成熟度）；**明确一线预期**（主动说「我自己写代码」，回应 JD 的「创业一线」）。

## 二、初创版 90 天计划：必答题的标准作答

「如果你入职，前三个月干什么」几乎必考。大厂答案（先建目录、先做治理、再上应用）在这个语境下是负分答案。初创答案的主线是：**先锁定一个能让人点赞的场景，用最小底座撑起它，控制点从第一天埋进去，但不追求平台完整。**

**第 1~2 周：盘点与选场景。** 盘点现有数据资产（公共库接入到什么程度、内部有什么、客户数据什么状态）、现有模型的消费方式（语料怎么进模型的）、找内部科学家和（如果有）标杆客户聊「哪个问题每周最耗时」。选场景的标准：高频痛点 + 数据可得 + 风险低（只读）+ 6 周能见效。默认候选：「靶点证据检索」（给定靶点，汇总文献/数据库/内部实验的可追溯证据）——它是发现域、只读、实体模型只需靶点—疾病—文献三个核心实体，业界（Genentech 研究Agent、Servier TURING）验证过价值。

**第 3~6 周：最小闭环。** 跑通「ChEMBL/UniProt/PubMed 接入 → [靶点实体对齐](./04-领域知识：生物医药研发数据实体标准与Ontology.md#term-entity-alignment)（内部 ID + 外部 ID 映射）→ 混合检索（BM25 + 向量）→ 证据卡片输出」的单链路；对齐用「LLM 初筛 + 专家裁决队列」的半自动模式，负责人亲自写对齐 pipeline 的核心部分。同步建三样轻量控制点：数据契约（YAML 文件）、数据清单+责任人（一张表）、调用日志（结构化记录每次检索的来源与权限）。

**第 7~10 周：评测与第一个使用者。** 建第一版评测：50~200 条专家标注问答（和科学家一起半天搞定种子集）+ claim-to-evidence 检查（每个结论对应证据片段，缺失即拒答）+ 10 条对抗样本（错误前提的查询、跨项目越权查询）。找 3~5 个内部科学家做真实使用，收集「引用是否可信、拒答是否合理」的反馈——**验收指标是专家采用率和引用正确率，不是问答次数**。

**第 11~13 周：定型与复盘。** 把闭环里可复用的部分标出来（对齐 pipeline、证据卡片格式、评测集），砍掉不可持续的临时方案，写一页「数据资产现状 + 下季度路线」给创始人；确定第一个招聘岗位（通常是数据工程师或知识工程/生信背景，取决于哪块瓶颈最大）。

**90 天结束时能回答的五个问题**（业界调研给负责人设的同款验收）：数据是否来自权威源且有明确责任人？实体定义是否跨场景一致？AI 能否定位原始证据？每次访问是否符合权限和许可？变更是否可回放？——这五个「是」，比「平台上线了」值钱得多。

## 三、实战题集：按考察层次分组

### 战略与规划层

**题 1：老板说「我们先做一个生物医药版 ChatGPT，数据以后再说」，你怎么回应？** 参考要点：不正面反驳，用业界证据重构顺序——Genentech/AZ 的公开体系都是数据产品先于 Agent；然后给替代方案：先做「垂直检索增强」的窄场景（可信但惊艳），垂直模型的语料建设与场景建设同步推进（两者本来就是同一件事的两面）。这道题考的是「能不能把技术判断翻译成创始人听得懂的语言」。

**题 2：公司同时服务自家管线和 ToB 客户，数据底座怎么设计才不会两边拉扯？** 参考要点：一套底座、两份契约——内部数据与客户数据物理/逻辑隔离（不同存储域 + 独立索引），共享的是本体、受控词汇、检索与评测组件；客户项目沉淀的通用能力（如某类文档的解析器）回流内部平台，但客户数据永不回流。本质是「平台复用组件、数据各自治理」。

**题 3：预算只够做三件事：实体对齐、图谱构建、评测体系，先做哪个？** 参考要点：评测和对齐必须先做，图谱第三。没有评测无法证明任何投入有效；没有实体对齐，图谱和检索都是垃圾进垃圾出。但注意对齐和图谱不是串行——对齐做到 80% 就够支撑第一版图谱（靶点—疾病—证据），剩余 20% 的人工裁决队列持续消化。这题考优先级的「乘法思维」：四因子公式里任何一项为零，整体为零。

### 架构与执行层

**题 4：生物医药 RAG 的检索层怎么设计？** 参考要点：五路混合（BM25 解决 EGFR 类专名与别名、向量解决段落语义、图谱约束实体关系、text-to-SQL 拿结构化数值、元数据过滤执行权限与质量分级）+ 证据卡片输出（文档 ID/版本/段落/权限策略）+ 最低证据数与拒答机制。主动对比通用 RAG 讲三个特有失败模式（专名向量失效、孤立数值不可解释、证据等级必须显式）。

**题 5：Agent 要帮科学家起草实验方案（涉及内部未公开数据），权限怎么设计？** 参考要点：按[四级风险分级](./02-生物医药数据与AI基础设施架构全景.md#sec-agent-rbac)落位——起草属「受控写入」，实验方案草稿可以生成但只在沙箱内、引用的数据带权限过滤、输出标记为草稿、进入实验系统需人工批准 + 幂等键；同时「跨项目数据导出」永远默认关闭。强调提示词约束不是安全边界，PEP（策略执行点）才是。

**题 6：实体对齐的 pipeline 怎么建，怎么证明它对？** 参考要点：公式（内部 ID + 外部 ID 映射 + 别名归一 + 冲突队列）；LLM 初筛 + 专家裁决；度量三率（精确合并/误合并/漏合并），**误合并权重最高**（虚假叠加证据比漏检危险）；黄金集 100 对起步，CI 里跑回归。

**题 7：评测体系从零建，没有标注预算。** 参考要点：分层组装——专家种子集（内部科学家半天 50 条）+ LLM-as-judge 初筛 + 抽样人工校准（judge 与人的一致率达标才可信，参照点富案例的 Kappa 校准方法论）+ 对抗集 + claim-to-evidence 检查；时间切分防污染。目标是「能发现方向性退化」，不是学术级基准。

### 交付与组织层

**题 8：客户要做私有化部署，他的安全团队会问什么，你准备什么证据？** 参考要点：按[三平面](./02-生物医药数据与AI基础设施架构全景.md#sec-tob)作答——控制面（租户/身份/策略/审计）、数据面（索引隔离/数据驻留）、证据面（默认不训练的合同条款与日志审计包、渗透测试报告、版本冻结与回滚方案）。强调「客户要的是可证明，不是断网」。

**题 9：前三个岗位招什么人？** 参考要点：第一个数据工程师（管道/治理/云，通用硬功夫）；第二个生信或知识工程背景（对齐与 Ontology 的领域脏活）；第三个视交付压力——交付顾问（懂客户现场）或评测工程师。招聘原则：**每个人都必须比负责人更专一块，但不招只专一块的**。

**题 10：你和算法团队（训模型的）边界怎么划？** 参考要点：他们负责模型结构与训练，我负责「模型吃什么、吃的东西可不可信、效果归因到数据还是模型」；冲突场景（数据配比分歧）用评测说话——设计能区分数据因素与模型因素的消融实验。主动提「不要求基础模型训练背景，但要懂模型如何消费数据」这条 JD 表述，说明边界是公司设计好的。

## 四、反问清单：面试后半场的攻守转换

反问要体现负责人视野（问的是战略，不是福利）。按重要度：

1. **数据资产的现状**：目前接入了哪些公共库、以什么方式（快照/增量）？内部管线数据（如果有湿实验）现在存在哪里、什么格式？——判断接手的是零还是有债务。
2. **第一个客户标杆**：ToB 交付目前走到哪一步（POC/付费/续约）？客户对数据侧的验收标准是什么？——判断交付压力与「证据面」的紧迫性。
3. **与模型训练的关系**：数据团队和算法团队怎么分工、语料建设的负责人是谁？——判断岗位是「AI-native 数据负责人」还是退化为「数据管道工头」。
4. **领域专家资源**：内部有多少可配合的生物医药专家、能投入多少时间做裁决和评测标注？——实体对齐和评测的天花板由这个决定。
5. **创始人的数据预期**：创始人认为数据侧 6 个月该交付什么？——对齐预期，也探公司对「数据决定 AI 上限」的信念是真是假。
6. **数据安全现状**：客户数据现在怎么隔离的、有没有过安全评审？——判断有没有已经欠下的合规债。

## 五、尽调清单：天使轮公司的双向考察

复用 [7.12 点富案例](../part7-ai-engineering/12-案例-点富科技大模型数据评测岗.md) 的创业公司尽调框架，做生物医药行业适配。**对负责人岗位，公司质量的权重高于薪资谈判**——你要把接下来两年押在这里。

**技术尽调**：团队的技术出身（AI 背景 vs 生物医药背景的比例决定你的互补价值）；开源产出和学术渊源（这个方向的公司通常有可验证的公开技术资产——开源模型、论文、数据集，质量是团队水平的最硬证据）；模型与数据的关系认知（问创始人「数据上你们最大的瓶颈是什么」，答得具体比答得宏大好）。

**商业尽调**：融资阶段与跑道（天使轮公司要问清现金跑道还剩多久、下一轮的里程碑是什么——你的 90 天计划最好和融资里程碑对齐）；ToB 还是自研管线为主收入路径（决定数据底座的建设重心是「可复制交付」还是「自家语料」）；客户名单的真实性（有付费客户 > 有 POC 客户 > 只有意向）。

**岗位尽调**：这个岗位是新设还是替换（替换要问前任为什么离开）；汇报线与决策权（汇报创始人 + 数据预算独立审批权是健康信号）；「负责人亲自产出」的预期强度（问「前三个月你期望我写的代码/做的方案占比多少」——双方预期错配是初创最大离职原因）。

**行业位置尽调**：对照业界参照系定位——大药企自建（复星模式）意味着 ToB 卖的是「能力差」窗口期；AI 制药同行的公开进展可以交叉验证赛道热度；监管动向（FDA/EMA/NMPA 的 AI 相关文件）决定 GxP 场景的打开速度。这个岗位的最优解出现在「公司有真实技术资产 + 有付费验证 + 创始人对数据瓶颈认知清醒」的三角里。

## 六、最后的检查表

面试前最后一晚，只过这张表：

| 检查项 | 达标标准 |
|---|---|
| 岗位本质 | 能一句话讲出「四因子公式」和「负责人也是产能」 |
| 两句反模式警告 | 能引用并展开「不只是 RAG 层面」「不是只做平台接口」 |
| 蓝图与裁剪 | 能画四层[蓝图](./02-生物医药数据与AI基础设施架构全景.md#sec-blueprint)，能当场说出[砍什么留什么](./02-生物医药数据与AI基础设施架构全景.md#sec-trim)及理由 |
| 实体统一 | 能讲[内部 ID + 外部 ID + 冲突队列公式](./04-领域知识：生物医药研发数据实体标准与Ontology.md#term-entity-alignment)和三率度量 |
| 生物医药 RAG | 能对比通用 RAG 讲三个特有失败模式和解法 |
| Agent 分级 | [四级风险表](./02-生物医药数据与AI基础设施架构全景.md#sec-agent-rbac)脱口而出，「提示词不是安全边界」敢说出口 |
| 90 天计划 | 能 5 分钟讲完，验收指标是专家采用率不是问答次数 |
| 评测从零建 | 50 条种子集 + judge 校准 + claim-to-evidence，能讲细节 |
| 反问 | 六个反问记住前三个 |
| 尽调结论 | 对「要不要去」有基于三角框架的明确判断 |

祝面试顺利。这个案例的最终目的不是拿 offer，而是验证一件事：**全书六章数据 + 七章 AI 的知识，加上一块新补的领域知识，能不能支撑一个「垂直领域 AI 数据体系从零到一」的负责人岗位**。答案是能——前提是按本章的方式把它们组织成体系，而不是当作孤立的知识点。
