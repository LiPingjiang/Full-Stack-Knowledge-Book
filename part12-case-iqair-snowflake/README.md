# 第十二章 · 案例研究：iQAir 空气质量数据平台与 Snowflake 数仓建设

> 以 iQAir 这类全球空气质量平台为案例，分析一个“从零散数据走向现代数仓”的数据工程岗位：为什么它会选择 Snowflake，为什么它既像数仓建设、又像湖仓建设，以及哪些能力属于通用数据工程，哪些能力是空气质量场景特有的。

## 本章定位

这一章和第九至第十一章略有不同：它不是严格对应一份公开 JD 的逐条拆解，而是根据**岗位方向描述 + iQAir 公开产品页面 + Snowflake 官方能力边界**重建出来的一套案例。

这样做的好处是：它更接近很多数据工程面试里的真实情形——面试官未必给你一份特别完整的 JD，但会给你一个业务背景（空气质量平台）、一个核心技术栈（Snowflake）、一个目标（把零散数据建成可靠数仓），让你现场讲清楚怎么设计、怎么落地、怎么取舍。

从 iQAir 公开页面可以直接反推出几个关键信号：
- 世界页公开展示了**3.5 万级监测站点**和**2 万级贡献者**量级，说明它是一个典型的**多源聚合平台**；
- 城市页同时展示**实时 AQI/PM2.5、历史数据、小时预报、日预报、天气信息、地理层级**，说明这不是单一指标看板，而是一套**时序 + 预报 + 地理空间 + 多标准派生**的混合型数据平台；
- 公开页面本身就是数据产品，这意味着下游不仅有 BI，还包括**站点页、城市页、排行榜、开放 API、年度报告**等多种消费形态。
