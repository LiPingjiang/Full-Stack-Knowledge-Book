## 一、Spark 原理

### 1.1 为什么比 MapReduce 快

短答：因为 Spark 尽量减少中间落盘，并把多步计算组合成 DAG 连续执行，同时 Spark SQL 层还叠加了 Catalyst / AQE 等优化能力。

### 1.2 RDD 怎么容错

短答：依赖 lineage 重算分区，而不是默认靠副本恢复。必要时可以 checkpoint 截断血缘。

### 1.3 宽依赖和窄依赖怎么理解

短答：窄依赖通常意味着可流水线执行，宽依赖通常意味着 Shuffle 和 stage 边界。

### 1.4 广播变量与累加器有什么区别

短答：广播变量解决的是“共享只读输入”，累加器解决的是“汇总执行指标”。

## 二、执行架构

### 2.1 Job、Stage、Task 是怎么划分的

短答：action 触发 job，宽依赖切出 stage，分区决定 task 数量。

### 2.2 DAGScheduler 和 TaskScheduler 分别做什么

短答：DAGScheduler 负责“切图”，TaskScheduler 负责“派工”。

### 2.3 本地化调度为什么能提速

短答：尽量让 task 靠近数据所在节点执行，减少网络传输。

## 三、Spark SQL 与执行计划

### 3.1 Catalyst 做了什么

短答：负责逻辑计划和物理计划优化，比如列裁剪、谓词下推、Join 选择等。

### 3.2 AQE 解决了什么问题

短答：让 Spark 能在运行时根据真实统计信息继续优化后续执行计划，例如自动合并小分区、动态切换部分 Join 策略、缓解部分倾斜问题。

### 3.3 DPP 与传统分区裁剪的区别

短答：传统分区裁剪依赖静态写法；DPP 会把维表过滤的结果动态传回事实表扫描阶段。

### 3.4 Hint 什么时候该用

短答：Hint 是兜底，不是第一反应。先看统计信息、AQE、SQL 写法是否已经足够合理。

## 四、性能优化

### 4.1 Shuffle 为什么慢

短答：因为它往往同时引入磁盘 IO、网络传输、序列化成本。

### 4.2 数据倾斜怎么处理

短答：先识别，再按 AQE / Broadcast / SQL 改写 / 加盐的顺序做，别一上来就加盐。

### 4.3 小文件问题怎么处理

短答：不能只靠 `coalesce`。要一起看 AQE、REBALANCE、最终写出目标和业务分布。

### 4.4 AQE 为什么不是万能的

短答：因为它只能在运行时特定物化点介入，也不理解你的业务写出目标，更解决不了前面 SQL 写法或数据读取阶段的问题。

### 4.5 为什么“加资源”经常不是第一反应

短答：因为主矛盾常常是扫描量、Join 写法、倾斜或分区设计，不是资源配置本身。

## 五、资源与内存

### 5.1 OOM 怎么分型

短答：先区分 Driver OOM、Executor OOM、容器超限被 kill，这三类处理方向不同。

### 5.2 YARN kill 和 JVM OOM 的区别

短答：前者更接近容器层面被外部终止，后者是进程自己抛出的 JVM 内存异常。

### 5.3 memory.fraction 的作用

短答：它影响 Spark 在统一内存管理下可用于执行与存储的空间比例，不该脱离任务形态单独讨论。

### 5.4 collect 为什么容易出事

短答：因为它把分布式结果集中拉回 Driver，很容易把问题从 Executor 侧转移到 Driver 侧。

## 六、调试运维

### 6.1 Spark 作业秒退怎么查

短答：优先看 Driver / AM 初始化日志，不要先盯 Spark UI。

### 6.2 日志体系怎么理解

短答：要区分 Driver、Executor、AM、Client，以及 stdout、stderr、syslog 的职责。

### 6.3 FileNotFoundException 怎么区分原因

短答：先看文件路径指向业务数据文件，还是本地 Shuffle 中间文件，根因完全不同。

### 6.4 Spark UI 正常但作业失败怎么办

短答：说明 Driver 通常已经起来了，此时优先转向执行期错误，而不是提交失败问题。

## 七、现代 Spark 话题

### 7.1 Spark Connect 是什么

短答：Spark Connect 是 Spark 3.4 引入的新 client-server 架构，适合更平台化、更远程、更多语言的使用方式。

### 7.2 YARN 和 Kubernetes 有什么差别

短答：差别不只是部署方式，而是日志入口、资源管理方式、本地盘生命周期、弹性回收和排障视角都不同。

### 7.3 如果让你设计 Spark 调优顺序，你会怎么做

短答：先减数据量，再修 SQL 与分布，再看资源与内存，最后调细节参数；全程以 UI 和日志证据为依据。
