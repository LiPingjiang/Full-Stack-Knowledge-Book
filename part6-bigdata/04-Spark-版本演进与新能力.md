# 6.4 Spark 版本演进与新能力

> 适用场景：想理解 Spark 为什么“今天和几年前不一样”  
> 阅读前提：已掌握 Spark 基础主线

## 一、如何看 Spark 演进

### 1.1 不要只按版本号记忆

记“3.0 有什么、3.2 有什么、3.5 有什么”当然有用，但更好的方式是按能力线理解：

- 执行优化能力怎么演进
- SQL 能力怎么演进
- 客户端使用方式怎么演进
- 运行环境怎么演进

### 1.2 按能力线理解版本升级

这样看版本演进，你会更容易知道：为什么某些旧经验在今天已经不再是最佳实践。

## 二、执行优化能力的演进

### 2.1 AQE

AQE 是 Spark 3.x 最重要的执行优化能力之一。它的价值在于：Spark 不再只依赖编译期估算，而能在运行过程中根据真实统计信息继续优化后续计划。

### 2.2 动态分区裁剪 DPP

DPP 是 Spark 3.x 在“少扫数据”层面的重要增强。它把维表过滤真正传导到事实表扫描阶段，使星型模型查询能显著减少不必要扫描。

### 2.3 更现代的 SQL 优化方式

今天再谈 Spark SQL 优化，主线已经不只是“调 `shuffle.partitions`”，而是要一起考虑：

- CBO
- AQE
- DPP
- REBALANCE
- 更清晰的 Explain 验证路径

## 三、客户端与使用方式的演进

### 3.1 Spark Connect 是什么

Spark Connect 是 Spark 3.4 引入的新 client-server 架构。它的核心价值是：把客户端与 Spark runtime 解耦，让交互式开发、平台接入、多语言客户端都更自然。

### 3.2 它解决了什么问题

它重点解决的是：

- 客户端与服务端强耦合
- 本地环境依赖过重
- 平台化接入成本高
- 远程交互式分析体验不稳定

### 3.3 对平台化和多语言客户端的意义

Spark Connect 的意义不只是“多一个协议”，而是 Spark 的使用方式开始更服务化、更接近平台化能力输出。

## 四、运行环境能力的演进

### 4.1 Kubernetes 支持增强

随着越来越多团队在容器环境中运行 Spark，Kubernetes 不再是“可选部署方式”，而是 Spark 运行模型的重要组成部分。

### 4.2 云原生运行方式的意义

云原生带来的不是单纯部署便利，而是：

- 更细粒度的资源治理
- 更强的平台化能力
- 更自然的弹性与多租户隔离

### 4.3 节点下线与弹性资源回收

当环境开始大量使用弹性伸缩、抢占式实例、自动下线节点时，Decommission 这类能力就变得更加关键。

## 五、Spark 4.x 前瞻

### 5.1 Declarative Pipelines

Spark 4.x 里值得关注的一条新方向，是更偏向现代数据工程编排与声明式表达的能力演进。它不一定是今天所有团队都必须用的主线，但值得建立认知。

### 5.2 哪些内容值得关注

值得关注的方向包括：

- 客户端与服务端进一步解耦
- 更强的 SQL / 声明式能力
- 更贴近现代数据平台的运行方式

### 5.3 哪些还不适合放进主线教材

前沿能力不等于今天就要大篇幅写进基础主线。对于大多数读者，Spark 3.x 的 AQE、DPP、云原生运行差异，仍然比更前沿的功能更值得先学扎实。
