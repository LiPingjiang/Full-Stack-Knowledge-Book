# 10.3 通用知识应用：高可用、多租户、SDK 与服务治理

密码平台同样是分布式系统，但安全要求改变了取舍：普通系统可接受短暂最终一致；密钥版本、授权策略和审计证据则必须有明确的线性化边界与故障语义。

多租户以 tenant_id 为授权域，而不只是表过滤条件。每一个 Key、Alias、Policy、审计事件和对象存储路径都绑定租户；缓存、MQ 消息和异步任务也必须携带并校验租户上下文。强合规客户可采用独立数据库、独立 HSM 分区或独立集群，普通租户使用共享表 + 行级安全控制。详见第六章 6.17。

CMSP/KMS 高并发通常集中在签名、验签、加解密与鉴权。应用层通过连接池、批量接口、异步审计和熔断保护 HSM；但“为了性能缓存明文密钥”不可接受。对于请求重试，查询和幂等的生成操作可重试，签名、扣减密钥池和轮换必须使用幂等键，避免重复副作用。

SDK 是安全能力的唯一推荐入口：统一 TLS/mTLS、请求签名、凭证刷新、超时、重试、错误码和 trace/request_id。服务网格 mTLS 只能保护服务间通道；KMS 仍要自行执行细粒度授权与审计。流量切片可用于 KMS 新版本灰度，但不是多租户强隔离。
